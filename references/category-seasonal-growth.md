# 细分品类、趋势与 B2B 采购周期

适用于既有站点按产品族/子品类/市场迭代。这里的日期和采购模型是内部规划方法，不能伪装成趋势平台的预测。涉及平台规则时，按 [来源表](search-sources.md) 重新核对。本模块不授权修改案例中的真实网站，除非用户当前任务明确要求。

## 1. 研究单元与证据账本

先定义 `category_id / parent / product_type / use_case / technical_attributes / buyer_role / market / language / year / existing_url / approved_fact_refs`。区分术语重叠：例如 activewear、sportswear、running wear 可交叉，不能因为同义词就生成相互竞争的薄页面。用意图与产品集合决定更新既有页、增加子页或只加筛选，不擅自改 URL。

每个品类建立四组种子：

1. 消费需求：产品名称、用途、痛点、材质/外观。
2. B2B 意图：manufacturer、OEM、private label、wholesale、supplier，加具体规格/采购角色，使用目标语自然表达。
3. 买家问题：选型/比较、测试方法、定制、样品、交货条件与风险。
4. 时间情境：目标市场的季节、节日、赛事、开学、财年/招投标/补库窗口；同时考虑工厂停工与运输拥堵。

**每条信号的最小记录**：id、category_id、platform、status（OBSERVED / HYPOTHESIS / UNAVAILABLE）、query/topic/prompt、market/language、period_start/end、granularity、search_type/filters、metric_definition、observed_value、comparison_basis、captured_at、source_url、raw_artifact、limitations、buyer_implication。未知值用 null，不填 0；例子、预测和实测分列。跨月重新下载的指数未必同尺度；不能直接拼接不同导出的 0–100 曲线。

## 2. 三类趋势与第一方需求交叉判断

### Google Trends

- 固定国家、日期窗、类别、搜索类型、词语或 Topic 口径；先查多年季节形状，再看一年和最近数周变化。尽量用至少两个完整周期判断复现性；历史不足写“候选季节性”。所有采集期都记录，不能凭经验填“全年 85–92”。
- 指数是所选范围内的相对兴趣，不是搜索量、市场份额或订单。比较词放进同一可比查询；跨批比较需共同锚点和明确重标定方法，否则分开展示。零/低样本不等于没有 B2B 需求。
- Rising 与 Top 分开；保存原始增长口径。Breakout 按平台定义，不把“+320%”同时写成 Breakout。分母为零、缺失或小样本时不造增长率，保留绝对样本/限制。
- 可用官方界面、导出文件或获准 API；先检查可访问能力，不假设存在公开免授权 API，不绕过登录/限流。第三方工具说明其代理口径。

### Pinterest Trends

分别记录搜索、收藏、购物信号与预测；筛选市场、时间、受众与指标，不能将某一受众/全球数据当成本地买家样本。平台功能与区域可用性以当前账号为准。视觉信号用于颜色、纹理、轮廓和使用场景假设，采购量需独立验证。

把视觉方向转成可生产的规格/配色/场景模块，并核对工厂能力、素材权利和产品真实性。灵感图不等于可直接盗用的商品图；高收藏不等于高询盘。预测单列为 FORECAST，不包装成已经发生的增长。

### AI search trends

“AI 搜索趋势”分为三种观测，**不默认存在全平台、全市场关键词搜索量**：

- **第一方平台可见度**：按账号可用性读取 Google AI Search 报告的实际维度、Bing AI Performance 的主题/意图/引用数据。它们描述本站在对应系统的表现，不等于全行业需求。没有导出或权限记 UNAVAILABLE。
- **固定问题组实测**：按买家角色、采购阶段和品类建立非品牌问题、品牌问题、对照问题。保留引擎/版本、国家/语言、日期、联网模式、完整问题、执行次数、回答和引用 URL；同条件重复采样，记录失败及分母，不挑最好一次。只说明该问题组的可见度与事实准确性，不称“AI 搜索量增长”。
- **第一方买家问题**：站内搜索、销售问答、去重 RFQ、CRM 需求，用匿名汇总识别规格/交期疑问；流量来源可能缺失，不能把所有未知来源算为 AI。第三方估计仅作有方法说明的辅助信号。

用交叉证据定优先级：真实供应能力/事实支持、B2B 意图与合格询盘强度、赶得上采购窗口、页面缺口、执行成本。无需把不同平台指数加总成一个“热度分”。消费者热度高而询盘弱时先验证小模块；搜索低但反复出现工程 RFQ 的产品仍可优先。一个来源的短期尖峰只支持实验假设。

## 3. 从目标到货/上架日倒排

每个市场/品类单独确定“消费者/使用需求窗口”“买家希望到货或上架的日期”“需求结束日期”。节日日期查当地当年日历，赛事查主办方，不用固定月份代替每年的实际日期。北/南半球分开，热带/雨季/度假市场按实际使用环境处理，不统一平移六个月。

设置如下区间（最短/最长，日历天）：采购评审、打样与确认、生产、验货、运输、清关、上架准备/缓冲；另设内容制作到可用的提前期。把材料备货和节假日停工计入实际环节或有说明的缓冲，注明是否已有库存。每个输入须有企业/物流来源，或明确标为假设；未知不能默认为 0。业务天需先按实际工作日历转换，不能和日历天混加。

```text
较保守的询盘启动日 = 目标到货/上架日 − 各环节最长天数总和
较紧的询盘启动日   = 目标到货/上架日 − 各环节最短天数总和
较保守的内容准备日 = 较保守的询盘启动日 − 内容提前期最长天数
较紧的内容准备日   = 较紧的询盘启动日 − 内容提前期最短天数
```

这是**串行流程的情景范围，不是统计置信区间，也不是保证最迟交货日**。已确认可并行的环节应用真实关键路径重算，不能把重叠时间重复相加；样品返工、旺季排产和运输尾部风险需要附加情景。若期限已过，输出“需要重新确认排产/补货/下一季”，不承诺加急交付。内容提前期用于制作和留出发现时间，不保证搜索引擎何时收录。

## 4. 随阶段改变页面任务

| 阶段 | 买家任务 | 网站实际动作与提示词重点 |
|---|---|---|
| 调研/淡季开发 | 选供应商、确定材料/规格、下一季概念 | 常青分类页、材料/工艺比较、真实案例与下载、开发咨询/样品 CTA；不靠虚构折扣制造需求 |
| 采购启动/打样窗口 | 样品、规格冻结、核算供应条件 | 品类矩阵、可选规格、MOQ/样品条件（有证据才写）、所需资料、样品申请与目标到货日期字段 |
| 批量采购/排产 | 确认交期、测试/验货和交货责任 | 生产/质检说明、真实能力与适用报告、RFQ 预填品类/市场/期望日期，提醒以确认订单为准 |
| 紧窗口/旺季补货 | 现货/补货/替代规格 | 仅基于真实库存、渠道与产能谈可供；窗口不够则引导询问可行方案，不能自动宣称“20天交货” |
| 季末/下一季 | 复盘、持续合作与新品开发 | 移除过期倒计时/交期承诺，保留有价值的 URL 和案例，更新内容及下一季询盘；不批量删页/改年号造新鲜度 |

首页季节模块只调排序和文案，常青导航/重要产品可达性保持。地区版本应有真实需求和独立内容；不按“品类×国家×节日”批量制造门页。季节变化是迭代触发条件，不是自动定时发布授权。

## 5. 服装案例的五个品类适配

下面是来自用户案例的**研究种子和页面结构**，不是 Wideway 或其他企业的实时数据/已验证能力。表中的时间线均需按上文重算。

| 品类 | 词组种子（需目标市场验证） | 需验证的买家问题/事实 | 季节情境与页面动作 |
|---|---|---|---|
| Activewear | squat proof leggings; seamless gym set; compression shirts | 不透/耐磨/起球测试、腰头/缝合、成分/GSM/尺码 | 常青与新年健身等活动分别验证；比较材料/工艺，给出真实测试条件与定制选项 |
| Sportswear | heavyweight hoodie; 400 gsm hoodie; french terry blanks | 克重/成分、缩水测试、版型、洗水、辅料与品牌使用 | 按目的地气候/街头服饰发布季检查；克重/面料导航与样品页，不能断言 GSM 是所有买家第一筛选项 |
| Running Wear | ultralight running singlet; marathon racing vest; split shorts | 重量测量条件、摩擦点、排汗/反光/缝合证据 | 主办方当年赛事和团队到货日倒排；赛事/团队采购页、尺码分配与到货需求字段 |
| Swimming Wear | chlorine resistant swimsuit; recycled swimwear fabric; ribbed bikini wholesale | 氯水/海水测试分别核实、湿态遮蔽、衬里/材料认证范围 | 泳池训练可常青；目的地夏季/度假系列分开；不把全球采购时间固定为10月至2月 |
| Beach Wear | upf 50 rashguard; sun protection hoodie; stretch boardshorts | UPF 检测条件、适用型号、耐洗/干燥测试、伸展/接缝 | 旅游/冲浪/户外与目的地气候；基于可核实报告做防晒选型，不自动推出医疗/防癌或绝对防护结论 |

扩展到其他行业时保留同一研究单元：家具/家居看零售系列和装修周期；礼品/包装看节庆到货与印刷确认；建材/机械看项目工期/招标/维护停机；农业品看产季/储存/物流；电子品看项目导入/生命周期/补货。消费季节性不明显时采用项目/补库周期，不能强套圣诞或夏季。

## 6. 对案例硬性数字与技术要求的处理

保留痛点→工程答案→采购参数→证据的结构，所有数值重新核验。FOB、MSRP、MOQ、5–7 天样品、工厂面积/机器/产能、具体品牌面料与认证不能凭示例写成公司承诺。每个声明绑定 SKU/主体、报告或报价版本、单位、测试条件、有效期和公开权限。

不要把“MSRP−FOB”算成净利润或保证毛利：若买家要求测算，明确模型还涉及运费、税费、渠道、折扣和退货等，并把情景假设与实际财务结果分开。关税/原产地/优惠资格按当期官方规则、HS 编码、生产与原产地条件核验，不能默认某国家/双基地就对欧盟和英国都零关税。

Google Trends 徽章只在可复核且对采购有用时呈现，并标地区/时间/口径；默认趋势情报留在规划报告，不作为工厂资质徽章。Schema 只标记适用的可见事实：B2B 询价页不编 AggregateOffer；自然语言 FAQ 有用不代表必有搜索富结果。llms 文件可选且只含获准公开资料，不宣称确保引用；机器人策略分别判断搜索、用户抓取与训练，不能照抄全放行名单。

## 7. 交付与复盘

新增 `trend-evidence`（含未取得的来源）、`procurement-calendar`、`category-page-actions`、`category-prompts`。每条页面行动写 category_id/market/window、原页面问题、信号引用、采购判断、改动、所需事实、CTA、owner/执行日期、复测与回退；同一品类允许不同市场不同动作。

把趋势采样时间与内容版本绑定，重大活动/供应变化时刷新；执行时检查最近数据，失去时效的证据不得充当“实时”。给出下一次复核日期/触发条件，但只有用户要求持续监测才设置自动任务。复盘按可比窗口记录样品申请、去重有效 RFQ、目标市场线索、回复与转化，使用上年同期或适当对照，不能把季节自然上涨归因于改站。
